# Архив технических заметок

Исторические измерения и проверки на рабочем Mac. Это не текущая инструкция
по сборке; актуальные команды находятся в [README](../README.md) и
[руководстве по релизам](releasing.md). Файлы `build/`, на которые ссылаются
замеры, локальные и не входят в репозиторий. Пути ниже приведены к корню проекта.

# Walone

Приложение для macOS 14+ и Windows 10/11. Разделы: «Атмосфера»,
«Моя музыка», «Клавиатура», «Настройки», «Таймеры» и «Статистика». Тема следует настройкам системы.

## Запуск и проверки

Проект использует **FVM Flutter 3.47.4** (`.fvmrc`). Матовое стекло
реализовано через `GlassSurface` пакета `g1455` с общим захватом `GlassHost`;
на macOS учитываются системные настройки уменьшения прозрачности
и повышения контраста.

На macOS включён **Impeller** (`FLTEnableImpeller=true`).
Для текущей sRGB-палитры используются BGRA8-буферы вместо BGRA10_XR;
Impeller MetalSDF и нативное разрешение сохранены. Совместимость внутреннего
selector Flutter проверяется нативным тестом (подробности замеров ниже).
В предыдущем локальном сравнении Release на этом Mac Skia уменьшал память в простое
со 106–114 до 72–83 МиБ по сравнению с Impeller MetalSDF; стеклянные панели
сохранены. Это результат для конкретного SDK, окна и компьютера.
Музыкальный плеер создаётся при первой загрузке трека, клавиатурный движок
и 24 голоса — при включении озвучивания или первом прослушивании примера.
Подготовка при включении сохраняет готовность к первому нажатию.
Опрос неизменного статуса клавиатуры
не обновляет интерфейс.

Дизайн-система описана в [docs/design-system.md](./design-system.md),
токены и темы — в `lib/core/design_system.dart`. Нейтральные поверхности,
системный шрифт, синий акцент и общая геометрия контролов применяются ко всем
разделам. Все панели, карточки, заголовки разделов и плеер используют один
матовый материал `FrostedPanel`: тонкую светлую кромку, мягкую тень и размытие
реального фона через общий захват `g1455`. `GlassPanel` задаёт карточкам
общую геометрию и акцентную рамку выбранного элемента; отдельного плоского
материала больше нет. Содержимое панели и подсказки не попадают в её размытие.
При уменьшении прозрачности и повышении контраста материал становится
непрозрачным, размытие и тени выключаются.

Меню начинается с группы «Фокус»: таймеры и статистика; далее группа «Звук»:
атмосфера, музыка, клавиатура. Настройки закреплены внизу, под компактным
плеером. В коротком окне меню прокручивается. Нижняя навигация узкого окна
использует тот же порядок. Идентификаторы разделов сохранены для команд
нативного меню и переходов из плеера.

В «Настройки → Материал интерфейса» настройка «Глубина интерфейса» задаёт
выраженность объёма: размытия фона, светлой кромки и мягких теней. Шкала
«Плоско → Объёмно» не обозначает процент оптической прозрачности. Изменения
применяются сразу и сохраняются автоматически. Прежнее значение и ключ
`transparency` сохранены для совместимости; миграция файла не требуется.
Выбор системной, светлой или тёмной темы сохраняется отдельно.

Автоматический режим включён по умолчанию на macOS, если доступен
недокументированный глобальный ключ `NSGlassTintAmount` с конечным значением
в диапазоне 0…1. Глубина вычисляется как `1 − tint`; это приближение системного
материала, а не измеренная прозрачность. Значение перечитывается при активации
и раз в две секунды в активном приложении. Отсутствие поддерживаемого значения
включает ручной режим. Настройки универсального доступа имеют приоритет:
уменьшение прозрачности и повышенный контраст отключают эффекты объёма.
Отключение автоматического режима возвращает сохранённое ручное значение.

Из этой папки:

```sh
fvm flutter pub get
python3 tool/prepare_assets.py
python3 tool/check_migration.py
fvm flutter analyze --no-pub
fvm flutter test --no-pub --concurrency=1
fvm flutter run -d macos
```

На Windows выберите `-d windows`. Нужны Visual Studio с C++ и Windows SDK;
для входа VK — WebView2 Runtime. Окно импорта определяет YouTube, SoundCloud
и VK по HTTPS-ссылке и проверяет запуск необходимых компонентов.
«Скачать недостающее» загружает их в `ImportTools` внутри папки данных Walone,
не меняя системный PATH. Можно также установить их самостоятельно в PATH
или `tools/` рядом с исполняемым файлом. Для YouTube нужны yt-dlp, FFmpeg
и Deno 2.3+ либо Node.js 22+; для SoundCloud — yt-dlp и FFmpeg; для VK — FFmpeg.

Загрузка использует HTTPS: yt-dlp и Deno из официальных GitHub Releases,
FFmpeg для Windows из BtbN/FFmpeg-Builds, для macOS — со сборочного сервера
Martin Riedl (`ffmpeg.martin-riedl.de`). Для Mac выбирается нативная сборка
под Apple Silicon или Intel, Rosetta для неё не требуется. Файлы GitHub
проверяются по SHA-256 из метаданных релиза; FFmpeg для Mac — по `.sha256`
того же архива после перенаправления latest на конкретную версию.
Все компоненты проверяются пробным запуском, а размер загрузки сверяется
с метаданными или Content-Length, если сервер его предоставляет.
При ошибке или отмене незавершённые загрузки удаляются; уже установленные
компоненты сохраняются для повторной попытки. Для обычной печати
и встроенных фоновых звуков сеть и эти инструменты не нужны.

На рабочем Mac **каждую** команду Flutter/Dart, сборку и тестовую app-сессию
выполняйте через общую очередь. Например:

```sh
python3 tool/resource_queue.py "$PWD/.fvm/flutter_sdk/bin/flutter" test --no-pub --concurrency=1
```

Скрипт входит в проект и использует общую для пользователя блокировку
в `/tmp`, чтобы согласовывать нагрузку между проектами и рабочими копиями.

Дальнейшие примеры сокращены; на этом Mac оборачивайте их этой же очередью.
Тесты нативных плагинов запускаются по одному файлу:

```sh
fvm flutter test integration_test/keyboard_native_test.dart -d macos --no-pub --concurrency=1
fvm flutter test integration_test/media_native_test.dart -d macos --no-pub --concurrency=1
fvm flutter test integration_test/desktop_native_test.dart -d macos --no-pub --concurrency=1
fvm flutter drive --driver=test_driver/integration_test.dart --target=integration_test/accessibility_native_test.dart -d macos --no-pub
```

Для явного запуска Impeller добавьте `--enable-impeller`, для сравнения со Skia —
`--no-enable-impeller`.

Сравнение памяти новых Release-процессов (по три запуска, 20 секунд каждый):

```sh
python3 tool/resource_queue.py python3 tool/measure_macos_memory.py /Applications/Walone.app --renderer impeller --output build/memory-benchmark/impeller
python3 tool/resource_queue.py python3 tool/measure_macos_memory.py /Applications/Walone.app --renderer impeller --no-glass --output build/memory-benchmark/no-glass
python3 tool/resource_queue.py python3 tool/measure_macos_memory.py /Applications/Walone.app --renderer skia --output build/memory-benchmark/skia
```

Измерение переподписывает отдельную временную копию с новым bundle ID,
копирует только JSON-метаданные и снимок SQLite, не запускает воспроизведение.
Установленное приложение и исходные настройки не меняются. В `result.json`
сохраняются физическая память за каждую секунду, медиана последних пяти
замеров и пик с момента запуска. Кэши macOS не сбрасываются; виртуальный
размер адресного пространства не используется. Полные сводки `vmmap` лежат рядом.

Доступность слайдеров обеспечивается `GainSlider` на основе CupertinoSlider:
Material Slider в используемом SDK повреждал нативное AX-дерево. Подписи,
фокус, стрелки, клик и перетаскивание сохранены.

### Память с Impeller — 20 октября 2026

Найден и исправлен лишний рендеринг при аудио: стандартный
`FramePositionUpdater` в audioplayers запрашивал следующий кадр Flutter
для каждого опроса позиции. Даже неизменное окно продолжало рисоваться
с частотой 120 Гц и удерживало дополнительные графические буферы.
`DesktopAudio` теперь использует `TimerPositionUpdater` с интервалом 100 мс.
Это частота обновления позиции, не частота звука или анимаций. Визуализация
музыки сохраняет свой таймер и интерполяцию; кроссфейд по-прежнему длится 2 секунды.

Release, M4 Pro, macOS 27.0.1, Flutter 3.47.4, Impeller MetalSDF в обоих
вариантах, полное окно Workspace 920×820 при DPR 2. Светлая тема, глубина
0,75, компактный плеер, отдельная копия метаданных. Громкость 0, но
нативные плееры действительно воспроизводят WAV. Каждый этап: 3 секунды
стабилизации и медиана трёх замеров `footprint` с интервалом в секунду.

| Состояние | До исправления, МиБ | После, МиБ |
|---|---:|---:|
| Начальный экран | 128,6 | 129,3 |
| Дождь, медиана трёх включений в одном процессе | 304,8 | 141,2 |
| Дождь + океан + поезд | 327,7 | 165,3 |
| Через 20 секунд после остановки | 149,9 | 147,7 |

Во время дождя экономия **163,6 МиБ (54%)**. Снимок `vmmap` первого
включения: IOSurface 69,1 → 23,0 МиБ; dirty-память `owned unmapped (graphics)`
124,2 → 12,2 МиБ. Это согласуется с устранением лишнего рендеринга, а не
с уменьшением аудиобуферов. Нативный регрессионный тест до изменения
обнаружил 241 запрос следующего кадра за 2 секунды; после — 0 при 20
обновлениях позиции. Проверены также пауза, перемотка и возобновление.

Остальные наблюдения до исправления:

- Обычная Release-сборка после 20 секунд простоя: 111,9 МиБ, пик 391,0 МиБ.
  У диагностических сценариев выше другие настройки и момент измерения.
- Пустой Flutter-интерфейс в том же native runner с зарегистрированными
  плагинами: 82,7 МиБ, пик 320,6 МиБ. Это не универсальный минимум Flutter.
- Три обхода экранов завершались на 131,0 / 151,3 / 134,0 МиБ:
  монотонного роста в этом коротком сценарии нет. Подготовка клавиатурного
  пула не дала крупного скачка памяти.
- Impeller на этом Mac включает wide gamut. Код Flutter выделяет 8 байт
  на пиксель поверхности вместо 4: около 23 МиБ против 11,6 МиБ у Skia
  при этом размере окна. Это ожидаемая стоимость поверхности.
- Кратковременный пик запуска исправление не уменьшило; он возникает
  также у пустого интерфейса. Долгие сессии, большая музыкальная библиотека,
  импорт и Windows в этом исследовании не проверялись.

Сырые результаты и снимки: `build/memory-investigation/`; сравнение —
`comparison.json`. Для повторения диагностическую сборку **не устанавливать**:

```sh
python3 tool/resource_queue.py .fvm/flutter_sdk/bin/flutter build macos --release --no-pub --target=tool/memory_probe.dart
python3 tool/resource_queue.py python3 tool/measure_macos_memory.py build/macos/Build/Products/Release/Walone.app --renderer impeller --probe media --runs 1 --output build/memory-investigation/repeat
python3 tool/resource_queue.py .fvm/flutter_sdk/bin/flutter build macos --release --no-pub --target=lib/main.dart
```

Также доступны `--probe empty` и `--probe workspace`. Используйте новую
папку вывода для каждого измерения. Последняя команда возвращает обычную
точку входа. Регрессионный тест: `integration_test/audio_frame_test.dart`.
Проверка исправления: нативный регрессионный тест, 46 целевых тестов аудио,
кроссфейда, возобновления, громкости и освобождения ресурсов; анализ
изменённых Dart-файлов — без замечаний.

### Сравнение рендереров при 120 Гц — 19–20 октября 2026

Локальный benchmark: MacBook Pro M4 Pro (14 CPU / 20 GPU, 24 ГБ),
macOS 27.0.1, Flutter 3.47.4, **Profile**, окно 920×820 при DPR 2.
Flutter сообщил 120 Гц; медианный интервал vsync в проверочном прогоне —
8,333 мс. По три отдельных запуска каждого рендерера, порядок
Skia → Impeller → Impeller → Skia → Skia → Impeller. Кэши не очищались.
Первый проверочный запуск в сводку не включён.

Использованы реальные `KeyboardPage`, `StatisticsPage`, `TimerPage` и
`WaloneGlassHost`, светлая тема, глубина материала 0,75. Нативный ввод
заменён заглушкой, каталог клавиатур настоящий; статистика содержит
365 детерминированных дней во временной SQLite. Пользовательские данные
не используются. Экраны показаны отдельно, без оболочки Workspace и плеера.
Живой захват фона выключен, как в широком окне с компактным плеером.
Уменьшение прозрачности и повышенный контраст проверены как выключенные.

После прогрева каждого экрана: шесть линейных прокруток между концами
списка по 2 секунды либо 12 секунд работающего помодоро. `FrameTiming`
собирается также в течение дополнительной секунды доставки последних
пакетов; у продолжающейся анимации эта секунда включает новые кадры.
Сводка объединяет сырые кадры трёх запусков, а не усредняет процентили.

| Сценарий | Raster p95, Skia / Impeller, мс | Raster p99, Skia / Impeller, мс | Build p95, Skia / Impeller, мс |
|---|---:|---:|---:|
| Прокрутка клавиатур | 1,605 / 1,468 | 2,200 / 1,838 | 0,995 / 1,109 |
| Прокрутка статистики | 2,033 / 1,954 | 2,894 / 2,257 | 0,342 / 0,392 |
| Анимация таймера | 1,456 / 1,329 | 1,575 / 1,446 | 0,994 / 1,051 |

Порог **8,333 мс** превышен хотя бы одной из стадий build/raster в
**1 из 14 061 кадров Skia (0,007%)** и **0 из 14 082 кадров Impeller**.
Единственный пик Skia — raster 8,712 мс на клавиатурах, только в одном
из трёх запусков. Это не доказательство устойчивого преимущества по рывкам.
`totalSpan` p95: клавиатуры 2,803 / 2,760 мс; статистика 2,518 / 2,590 мс;
таймер 2,637 / 2,536 мс. Build и raster работают конвейером, поэтому
их сумма не используется как критерий пропуска кадра.

**Вывод:** в этих сценариях оба рендерера имеют большой запас под 120 Гц.
Impeller уменьшил raster p95 примерно на 4–9%, p99 на 8–22%, но не дал
сопоставимого ускорения всего кадра. Оснований включать его только ради
120 Гц по этому замеру нет. После сравнения по запросу пользователя возвращён Impeller.
Ранее приведённое сравнение памяти — отдельное Release-измерение;
память, CPU, энергопотребление и холодный старт здесь не измерялись.

Это сравнение стадий Flutter, **не измерение показанных композитором кадров**:
редкие `totalSpan` доходили примерно до 15,5 мс при быстром build/raster.
Результат не распространяется на Windows, другие GPU, полный Workspace,
плавающий плеер с живым фоном, медиавоспроизведение и изменение размера окна.
На Windows локальный runner не задаёт явное отключение Impeller;
замер Windows в этой macOS-среде не выполнялся.

Воспроизведение из корня репозитория (на Mac через общую очередь):

```sh
python3 tool/resource_queue.py python3 tool/compare_renderers.py --device macos --runs 3
python3 tool/compare_renderers.py --device macos --summarize-only
```

На Windows используется `python tool/compare_renderers.py --device windows --runs 3`
с установленным SDK из `.fvmrc`. Сырые кадры и логи каждого запуска сохраняются
в `build/renderer-benchmark/`, агрегаты — в `summary.json`.
Benchmark: `integration_test/renderer_performance_test.dart`.
Все шесть измерительных запусков успешно завершены.

## Возможности

Разделы интерфейса создаются при открытии и освобождаются при переходе;
позиции прокрутки и фильтр клавиатур сохраняются в памяти сессии. В компактном
режиме панели используют `GlassBackdrop.color`; с плавающим плеером
сохраняется живой захват фона.
Амплитуды музыкальной визуализации хранятся в компактном `Float32List`.
Плееры птиц и чаек освобождаются после окончания записи, до следующего события.
После завершения, отмены или ошибки импорта VK авторизованный WebView
закрывается с сохранением cookies. Незавершённый вход остаётся открытым.

«Клавиатура»: 20 наборов, каталог и история выбора, поиск, независимое
прослушивание до выбора, четыре группы клавиш и поле пробной печати.
macOS требует «Мониторинг ввода»; Secure Input временно приостанавливает
обработку. Удержание не повторяет звук. Символы и отдельные события нажатий
не пишутся на диск. Глобальный ввод и воспроизведение остаются в нативном коде.

«Статистика»: выбор ежедневной цели и серии по прослушиванию или концентрации,
отдельные цели по времени (по умолчанию 30 и 60 минут соответственно),
необязательная независимая цель по нажатиям, текущая и лучшая серии дней.
Календарь за последние 12 месяцев показывает прослушивание, нажатия или концентрацию оттенками
зелёного; выбор дня раскрывает его итоги. Насыщенность соответствует доле
дневной цели; без цели по нажатиям используется шкала до 1000 нажатий.
Итоги и рейтинги плейлистов/атмосфер доступны за последние 7 и 30 дней
и за всё время. Переименование обновляет название в рейтинге, удаление
плейлиста или набора не стирает его историю. Несохранённые миксы объединяются
под названием «Свой микс».

Концентрация включает рабочие фазы помидоро и запущенный секундомер,
независимо от музыки. Паузы и отдых помидоро исключаются; переключение
режима не останавливает другой таймер. При наложении режимов общее время
концентрации считается один раз, а длительности помидоро и секундомера —
отдельно. Интервалы берутся из TimerCubit, включая переходы фаз, задержанные
тики и фоновый отсчёт после сна; они разделяются по местной полуночи.
Сброс таймера не удаляет уже записанную историю. Серию определяет выбранная
пользователем метрика: прослушивание или концентрация. Цели обоих режимов
настраиваются независимо от 1 до 1440 минут и сохраняются при переключении.
Для календаря используются цели соответствующего дня. Все три показателя видны за сегодня, выбранный день
и выбранный период.

Экран использует независимые BlocSelector для целей, дней календаря,
выбранного дня, периода и рейтингов. Изменение одного дня не создаёт заново
годовую сетку; смена периода не перестраивает календарь. Строки рейтингов
создаются лениво через SliverList. В таймере плавное кольцо обновляется
каждые 200 мс отдельно от подписей и элементов управления.

Учитывается фоновое воспроизведение с ненулевой громкостью в Walone;
системная громкость не проверяется. Общее время не удваивается при
одновременной музыке и атмосфере. Глобальные нажатия считаются только при
прослушивании, независимо от озвучивания клавиатуры. Паузы, сон и разрывы
таймера свыше 5 секунд не начисляют время. Нажатия опрашиваются раз в секунду
и относятся к дню опроса. Границы дней определяются местным временем.

В «Статистика → Настроить статистику → Цель и серия дней» выбирается метрика
серии, ниже настраиваются обе цели и независимая цель по нажатиям. Там же
включается/выключается сбор и очищается история с подтверждением. Метрика и
цели меняются для сегодняшнего и будущих дней; прошлые цели и выбор метрики
сохраняются. Серия может включать соседние дни с разными метриками, если в
каждый день выполнена действовавшая тогда цель. Пока сегодняшний день не закончился,
вчерашняя серия остаётся действующей. Отключение сбора сохраняет историю,
очистка истории сохраняет настройки. История начинается с установки этой
версии и хранится бессрочно, только на устройстве.

Суточные суммы, рейтинги и настройки статистики хранятся через Drift в
`statistics.sqlite` в каталоге данных `WaloneFlutter`. Запись выполняется
транзакциями каждую секунду активности, при переключениях воспроизведения и выходе;
экран подписан на изменения Drift и обновляет показатели после записи в базу.
При аварийном завершении возможна потеря последнего несохранённого интервала.
Настройки приложения и медиатека продолжают использовать JSON-файлы.
Схема статистики v2 добавляет показатели концентрации и переключатель
календаря, v3 — отдельную цель по концентрации и метрику серии в настройках
и суточных снимках. Миграции сохраняют данные v1/v2; для старых дней серия
продолжает определяться прослушиванием. Снимки схем находятся в
`test/drift_schemas`, сгенерированные средства проверки миграций — в
`test/statistics_migrations`. После изменения схемы обновите снимок и средства
проверки через ту же очередь ресурсов:

```sh
fvm dart run drift_dev schema dump lib/features/statistics/data/statistics_database.dart test/drift_schemas
fvm dart run drift_dev schema generate test/drift_schemas test/statistics_migrations
```

После изменения схемы/таблиц код Drift генерируется из исходников:

```sh
fvm dart run build_runner build
```

Эту команду также нужно запускать через общую очередь ресурсов, описанную выше.

«Атмосфера»: 10 источников с отдельными уровнями, общая громкость,
сохранение/обновление/переименование/удаление наборов и отмена переключения.
Отдельная громкость атмосферы сохраняется в `atmosphere.json` как
`backgroundVolume`; старые файлы получают значение 1 без изменения звучания.
Она влияет только на фон, а общий уровень — на все источники.
Наборы включают выбор, уровень и включение клавиатуры. Общая пауза и таймер
15/30/60 минут действуют также на музыку. Сон и отключение наушников
приостанавливают звук; после прерывания нужен ручной запуск.

«Моя музыка»: плейлисты, копирование файлов и drag-and-drop, дедупликация,
экспорт всей медиатеки и импорт архива для переноса между macOS и Windows.
«Экспорт медиатеки» сохраняет `Walone-music.zip`: аудиокопии, названия треков,
названия и порядок плейлистов, порядок треков и пустые плейлисты.
На другом ПК нажмите «Импорт архива» в «Моя музыка» и выберите этот файл.
Существующие плейлисты сохраняются, импортированные добавляются отдельно;
повторный импорт снова добавит плейлисты. Аудио с одинаковым SHA-256 хранится
одной копией; его название и метаданные берутся из архива. Настройки плеера
на принимающем ПК сохраняются. Вход VK и настройки приложения не переносятся.
Архив имеет версию формата 2: `walone.json`, `audio/001 - Название.<расширение>`
и `playlists/001 - Название плейлиста.m3u8`. Имена ZIP и содержимое плейлистов
записаны в UTF-8: кириллица, иероглифы, арабский и emoji сохраняются.
После распаковки `.m3u8` ссылаются на треки в соседней папке `audio`;
сохраняйте обе папки рядом. Номера предотвращают совпадения имён, а запрещённые
в Windows символы заменяются на `_`; слишком длинные имена файлов сокращаются.
Полные исходные названия остаются в манифесте и восстанавливаются при импорте
в Walone. Старые архивы версии 1 со служебными SHA-256-именами поддерживаются.
ZIP записывается без повторного сжатия аудио; импорт принимает такой же формат,
проверяет структуру, связи и SHA-256 до сохранения медиатеки. Ошибка или отмена
до сохранения не добавляет плейлисты. Поддерживается также ZIP Deflate.

Музыкальный плеер:
Полоски логотипа в боковом меню и значка трея показывают реальную амплитуду текущего трека
с учётом позиции и громкости. Анализ выполняется в фоне через FFmpeg,
без сохранения PCM на диск. При паузе, уменьшении анимации или отсутствии
FFmpeg отображается исходная иконка. Анализ ограничен первыми шестью часами трека.
Окно и трей используют один анализ. Скрытие окна сохраняет воспроизведение
и анимацию значка трея. При паузе музыки расчёт отменяется, амплитуды
освобождаются, значок трея возвращается к исходному виду. После снятия паузы
анализ запускается заново. Если подписка трея отключена, скрытие окна также
освобождает анализ. Обновление значка не меняет меню и текст таймера в трее.
Play/Pause, очередь, перемотка, shuffle и repeat. Кнопка «Убрать плеер в левое меню»
переносит управление в боковую панель и освобождает контент. В мини-плеере
управление разделено на полоски музыки, атмосферы, клавиатуры и общего уровня.
Все каналы остаются на постоянных местах при переходах между разделами.
Компактный плеер показывает позицию и длительность трека, позволяет перематывать
и раскрывать полное название нажатием. Общая пауза выделена отдельным блоком
с кнопкой возобновления; выбранные источники атмосферы показывают статус паузы.
У музыки громкость, shuffle и repeat доступны напрямую, без меню.
«Развернуть плеер» возвращает оверлей.
Режим сохраняется в `appearance.json`. На узком окне без бокового меню
временно показывается полная панель; при расширении компактный режим возвращается. Просмотр другого списка
не меняет звучащую очередь. Удаляются только неиспользуемые локальные копии.
YouTube сохраняет запись новым списком, используя главы/таймкоды для нарезки;
SoundCloud — публичные полные записи и плейлисты; VK — треки/альбомы/плейлисты
через отдельное окно входа. Cookies остаются внутри WebView. Отмена сохраняет
уже добавленные VK/SoundCloud-треки. Ручная нарезка доступна в меню трека;
ошибка сохраняет исходник, успешная замена касается только выбранного списка.

Закрытие скрывает окно в трей; выход сохраняет позицию и отменяет импорт.
Автозапуск включается явно в настройках, стартует без окна и звука.
macOS использует SMAppService, Windows — запись WaloneFlutter в HKCU Run.
Для изменения системного разрешения есть переход в настройки ОС.

## Таймеры

Отдельная вкладка «Таймеры» содержит помодоро и секундомер. У помодоро
настраиваются работа (1–180 минут), отдых (1–60 минут) и повторы (1–12).
Каждый повтор включает работу и отдых; этапы переключаются автоматически
с разными звуковыми сигналами: нисходящая мелодия завершает работу,
восходящая — отдых, включая последний в цикле. После сна звучит только
сигнал последнего завершённого этапа. Доступны запуск, пауза, сброс и пропуск этапа.
Для изменения настроек начатую сессию нужно сбросить.

Оба режима могут работать одновременно и продолжают отсчёт при смене вкладки,
скрытом окне и после сна компьютера. «Показывать в трее» выводит выбранный
режим: на macOS время находится рядом со значком в строке меню,
на Windows — в подсказке значка и контекстном меню. Из меню можно открыть
вкладку, приостановить/продолжить или сбросить выбранный таймер.
После завершения приложения сессии и настройки таймеров сбрасываются.

## Данные

Данные находятся в `getApplicationSupportDirectory()/WaloneFlutter`:
`Music/library.json`, аудиокопии, `atmosphere.json`, `keyboard-history.json`, `appearance.json`
и профиль WebView. Повреждённые манифесты защищены от перезаписи.

Калибровка и чувствительность хранятся в UserDefaults приложения
`dev.soyjanks.walone.flutter`. Данные из прежнего приложения уже перенесены;
кнопки и код чтения его медиатеки и UserDefaults удалены. Текущие данные
и их формат сохранены. Загрузка калибровки из сводки измерений остаётся доступна.

## Эксперимент с вибрацией

На совместимом Mac доступны чувствительность, личная калибровка из JSON,
индикатор интенсивности, серии мягкой/обычной/сильной печати, сбор амплитуд,
сброс и экспорт сводки schema 5 с диагностикой задержек. Это измерение вибрации
корпуса, а не классификатор силы. На Windows доступно обычное озвучивание.
Без свежего потока датчика используется обычный звук.

Открыть «Настройки» → «Эксперимент с вибрацией». Для реального потока нужна
отдельная короткая сессия sensor-probe с повышенными правами. Сначала прочитайте
[ограничения и свойства датчика](./sensor.md).
Приложение всегда работает от обычного пользователя. Скрипт ниже запрашивает
sudo в терминале только для probe; `--approved-root-activation` означает
разрешение на временное изменение свойств SPU, а `--approved-root-read` — чтение
без активации. Запускайте это только после осознанного разрешения такой сессии:

```sh
bash tool/sensor_experiment.sh --approved-root-activation "$PWD/build/macos/Build/Products/Debug/Walone.app"
```

Сначала соберите свежую `.app` и завершите другие копии Walone.
Сессия ограничена 120 секундами; после окончания GUI остаётся в обычном режиме.
Для калибровки выключите озвучивание, соберите минимум по 20 отдельных нажатий
одной клавиши/пальца на режим без пропусков и экспортируйте сводку. Загрузчик
принимает schema 5 с разделёнными центральными диапазонами; ошибочный файл
не заменяет действующую калибровку.

Проверка на искусственном сигнале без оборудования и sudo (из этой папки):

```sh
swiftc -module-cache-path /private/tmp/walone-sensor-modules macos/Runner/ImpactEstimator.swift macos/Runner/SensorStream.swift macos/Runner/IntensityCalibration.swift macos/Runner/SensorExperiment.swift tool/sensor_check.swift -o /private/tmp/walone-sensor-check
/private/tmp/walone-sensor-check
```

На рабочем Mac собирать и запускать эту проверку последовательно через очередь.

## Устройство самостоятельного проекта

Для сборки, генерации ресурсов, тестов и установки достаточно корня репозитория.
Архив прежнего нативного приложения удалён.
Код переноса пользовательских данных из прежней версии удалён после завершения переноса.

- `macos/Runner/KeyboardAudio.swift` — нативное воспроизведение клавиатуры.
- `macos/Runner/AudioOutputMonitor.swift` — наблюдение за аудиовыходом.
- `macos/Runner/SensorStream.swift`, `ImpactEstimator.swift`,
  `IntensityCalibration.swift`, `SensorExperiment.swift` — поток и расчёт датчика.
- `tool/sensor-probe.c`, `sensor_experiment.sh`, `sensor_check.swift` —
  ограниченная аппаратная сессия и проверка искусственного сигнала.
- `tool/resource_sources/` — исходные записи, подготовленные PCM, параметры
  нарезки, лицензии, авторство и исходники VK JavaScript. Они не упаковываются
  в приложение целиком. Инструменты подготовки находятся в `tool/audio/`.
- `assets/` — сгенерированные ресурсы приложения. Не редактируйте их вручную.

`python3 tool/prepare_assets.py` без сети собирает каталог из локального
KeyboardAudio.swift и копирует ресурсы из `tool/resource_sources/` в `assets/`.
`python3 tool/check_migration.py` проверяет локальные пути Xcode, состав, SHA-256
и побайтное совпадение WAV, лицензий и VK-скриптов с источниками проекта.
`tool/resource_sources/bundled-sha256.json` фиксирует контрольные суммы ресурсов; при намеренном изменении записей обновляйте эталон отдельно.

Инструменты повторной подготовки звуков (нужен FFmpeg):

```sh
python3 tool/audio/prepare-keyboard-sounds.py
python3 tool/audio/prepare-model-sounds.py
python3 tool/audio/prepare-extra-keyboards.py
python3 tool/audio/prepare-atmosphere.py --source-dir build/atmosphere-originals
python3 tool/prepare_assets.py
python3 tool/audio/check-keyboard-clips.py --report build/catalog-audio-quality.json
python3 tool/audio/check-atmosphere-clips.py
```

Для повторной подготовки только птиц и чаек добавьте к
`prepare-atmosphere.py` флаг `--only birds seagulls`. Фрагменты замедлены
до 85% темпа без изменения высоты звука, приглушены, плавно входят за
1 секунду и затухают за 3 секунды. Паузы между ними составляют 12–36 секунд.
При выключении атмосферы или отдельного слоя звук затухает за 0,8 секунды.

Первые два скрипта загружают закреплённые upstream-источники при явном запуске.
Дополнительные клавиатуры используют встроенные оригиналы и загружают только
отсутствующие файлы с проверкой SHA-256. Атмосфера использует отдельную папку
оригиналов; загрузка разрешается явным флагом `--download`. Для обычной сборки
повторная обработка записей и сеть не нужны.

## Локальная установка macOS

Иконка — персиковая W-волна на тёмном сливовом фоне.
Векторный исходник — `tool/app_icon.swift`; PNG всех размеров находятся
в `macos/Runner/Assets.xcassets/AppIcon.appiconset` и включаются Xcode в сборку.
При изменении исходника пересоздайте их из этой папки:

```sh
xcrun swift tool/app_icon.swift macos/Runner/Assets.xcassets/AppIcon.appiconset windows/runner/resources/app_icon.ico
```

Завершите установленную Walone. Из этой папки через общую очередь:

```sh
python3 tool/macos_release.py --flutter "$PWD/.fvm/flutter_sdk/bin/flutter"
python3 tool/macos_release.py --verify-only
```

Скрипт собирает Release с `--no-pub`, подписывает сертификатом Apple Development
или Developer ID Application, проверяет designated requirement и устанавливает
`/Applications/Walone.app`. Прежняя версия хранится только до завершения
проверки и регистрации новой; при ошибке замены, проверки или регистрации
установщик возвращает её. После успешного обновления временная копия,
предыдущая версия и Release `.app` в `build` удаляются без переноса в Корзину.
Инкрементальные кэши сохраняются. Архивы в `dist/macos/` больше не создаются;
сведения о последней установке перезаписываются в `build/macos-installation.json`.
`--skip-build` требует существующей Release `.app`; после успешной установки
для следующего обновления нужно снова выполнить сборку. При нескольких сертификатах
задайте `WALONE_SIGNING_IDENTITY`. Для распространения нужны Developer ID,
timestamp и notarization; локальная Development-подпись их не заменяет.

Результаты текущей проверки и оставшаяся ручная приёмка:
[FEATURE_PARITY.md](FEATURE_PARITY.md).

## Проверка времени жизни аудио — 20 октября 2026

В `AtmosphereAudio` исправлены гонки отмены: незавершённая загрузка больше
не публикует и не запускает плееры после `stop()` или более нового `update()`.
Ранее перекрывающиеся загрузки одного слоя могли затереть ссылку на плеер
без `dispose()`. Подготовка птиц/чаек также проверяет отмену после асинхронных
операций, а повторное освобождение одного плеера использует общий Future.
Три регрессионных теста воспроизводили потерю ресурсов/запуск после остановки
до исправления и проходят после него. Это проверка конкретных гонок;
она сама по себе не измеряет экономию RAM и не исключает другие утечки.

Для проверки обычного музыкального тракта добавлен сценарий `--probe music`
в `tool/measure_macos_memory.py`. Он использует диагностическую сборку
`tool/memory_probe.dart`, временную медиатеку и встроенный WAV: пять циклов
воспроизведения/паузы с визуализацией, затем 20 секунд простоя. Пользовательская
медиатека не изменяется. Результаты текущей проверки находятся в
`build/memory-lifecycle-audit/`. Диагностическую сборку не устанавливать;
после замеров собрать обычную точку входа `--target=lib/main.dart`.

## Снижение графической памяти — 20 октября 2026

В закреплённом Flutter 3.47.4 `FlutterDartProject.enableWideGamut` автоматически
включает расширенный цветовой формат на поддерживаемом Mac. `FlutterSurface`
выделяет BGRA10_XR по 8 байт/пиксель. Текущие цвета Walone — sRGB, поэтому
`WaloneDartProject` в `MainFlutterWindow.swift` выбирает BGRA8 (4 байта/пиксель).
Это внутренний selector Flutter, а не публичный API: при обновлении SDK
обязательно запускать `testSRGBProjectKeepsImpellerAndFlutterSelectorContract`
и повторять визуальные/нативные замеры. При добавлении HDR/P3-контента решение
нужно пересмотреть. Ключ `WaloneEnableWideGamut=true` в Info.plist возвращает
прежний формат для контрольных замеров; в обычной сборке ключ отсутствует.

Контроль: одна Release-сборка, Impeller MetalSDF, окно 920×820/DPR 2,
реальное воспроизведение встроенного WAV по кругу, визуализация и стекло включены.
Три пары свежих процессов, порядок wide/sRGB, sRGB/wide, wide/sRGB.
На каждом этапе — медиана трёх измерений `footprint`, затем медиана запусков.

| RAM при музыке, медиана | 400,6 | 362,4 |
| RAM при музыке, три запуска | 400,6 / 401,0 / 386,2 | 351,8 / 366,6 / 362,4 |
| Пиковая RAM процесса, медиана | 426,5 | 392,3 |
| IOSurface при музыке, первая пара | 46,1 | 23,2 |

Экономия RAM при воспроизведении — 38,1 МиБ (9,5%) в этом сравнении;

## Оставшаяся графическая память — дополнительная проверка 20 октября 2026

После перехода на BGRA8 новый исходный замер дал 364,6 МиБ при музыке
и 129,3 МиБ после паузы. Диагностические отключения по одному, при том же
окне 920×820/DPR 2: без анимации строки меню — 355,9 МиБ, без тени окна —
356,5 МиБ, без стекла — 361,0 МиБ. Разница находится в наблюдавшемся разбросе
между запусками; дополнительная устойчивая экономия не подтверждена.
Три заключительных контрольных запуска со всеми эффектами дали
368,6 / 352,4 / 367,6 МиБ (медиана 367,6 МиБ), подтверждая этот разброс.
Все отключения удалены из кода приложения. При уменьшении окна до 760×680
расход составил 329,9 МиБ, но это другие условия, а не оптимизация приложения.

Минимальная Flutter-сцена с одним анимированным прямоугольником без музыки
потребляет 199,6 МиБ, после остановки — 72,7 МиБ. Dirty
`owned unmapped (graphics)` меняется с 5,7 до 117,7 МиБ — на 112 МиБ.
В полном приложении эта категория при музыке составляет 124,2 МиБ,
на паузе — 12,2 МиБ. Отключение строки меню и тени окна прирост не устраняет;
меньшее окно также оставляет прирост около 112 МиБ.

Чтобы отделить Flutter от Metal, добавлен самостоятельный
`tool/metal_memory_probe.swift`. Он использует только Foundation/Metal,
две BGRA8-текстуры 1840×1640 и очистку render pass каждые 50 мс, ожидая
завершения команды. В отдельном процессе получено: 4,55 МиБ до кадров,
149,86 МиБ во время кадров, 35,56 МиБ через несколько секунд после их остановки.
`MTLDevice.currentAllocatedSize` при кадрах и после остановки одинаков:
25 919 488 байт (24,72 МиБ). Ограничение очереди команд с 64 до 1 не помогло:
оба процесса потребляли около 149,7 МиБ при кадрах.

Это воспроизводит большой временный расход в Metal без Flutter, аудио,
стекла и визуализации Walone. Результат указывает на существенный вклад
системного графического тракта на данном Mac (M4 Pro, macOS 27.0.1), но не
идентифицирует внутренний буфер драйвера и не доказывает отсутствие иных
источников расхода в приложении. Без изменения частоты кадров, разрешения,
оформления или движка безопасного способа убрать этот объём пока не найдено.

Сырые отчёты находятся в `build/graphics-memory-followup/`, включая
`native/lifecycle.json`, `native/lifecycle.log` и `native/*-vmmap.txt`.
В `measure_macos_memory.py` добавлены `median_playing_mib` и
`--max-playing-mib`: бюджет теперь можно проверять именно при музыке,
а не только на последнем этапе паузы. Проверка исходного сценария
`--probe music-active --runs 1 --max-playing-mib 330` закономерно завершается
с ошибкой `364.6 > 330.0 MiB`; это диагностический порог, не обещанный лимит.
Прежний `--max-mib` по-прежнему относится к последнему этапу.

## Проверка настроек Flutter и Metal — 20 октября 2026

Продолжение на том же M4 Pro / macOS 27.0.1. Проверены публичные варианты
Metal без изменения Walone: две BGRA8-текстуры 1840×1640, 200 кадров,
пауза 50 мс между отправками, ожидание завершения каждой GPU-команды.
Каждый вариант запускается отдельным процессом; RAM — медиана трёх
измерений `footprint` в активной фазе. Во всех Metal 3 вариантах лимит
незавершённых command buffers равен 1.

| Вариант | Активная RAM, МиБ | p95 отправки и ожидания GPU, мс |
|---|---:|---:|
| Metal 3, private-текстуры | 149,92 | 1,06 |
| Shared-текстуры | 149,88 | 1,09 |
| Untracked-текстуры | 149,72 | 1,03 |
| Command buffer с unretained references | 149,83 | 1,07 |
| Metal 4, переиспользуемые command buffer и allocator | 149,88 | 1,03 |

Во всех пяти процессах выполнены 200 кадров, а после измерений проверены
ожидаемые BGRA-значения центрального пикселя обеих текстур через GPU readback.
`MTLDevice.currentAllocatedSize` одинаков: 25 919 488 байт.
Shared переносит часть памяти из `owned unmapped (graphics)` в другую
категорию, но общую физическую память не уменьшает. Измерения времени
относятся к минимальному примеру, не к плавности интерфейса Walone.

Metal 4 позволяет переиспользовать память кодирования команд — это описано
в [документации Apple](https://developer.apple.com/documentation/Metal/understanding-the-metal-4-core-api).
Но здесь такой переход не убрал большой расход. В закреплённом Flutter
3.47.4 Metal-backend Impeller использует прежние `MTLCommandQueue` и
`MTLCommandBuffer`; его перенос на Metal 4 не является переключателем
Info.plist и по этим замерам не обоснован как исправление найденного расхода.

Дополнительно проверены исходники закреплённого движка:

- `shell/common/rasterizer.cc`, `SetResourceCacheMaxBytes`: лимит применяется
  к `GrDirectContext`; у `GPUSurfaceMetalImpeller::GetContext()` результат
  `nullptr`. Настройка кэша Skia этот расход Impeller не ограничит.
- `impeller/renderer/backend/metal/allocator_mtl.mm` и
  `swapchain_transients_mtl.mm`: временные MSAA/depth-stencil поверхности
  уже используют memoryless-хранилище на поддерживаемых Apple GPU.
  Выходные текстуры нельзя безусловно сделать memoryless: их содержимое
  должно сохраняться между проходами и для показа окна.
- `RenderTargetCache` хранит неиспользуемые цели ещё четыре кадра;
  публичного macOS-параметра размера этого пула в проверенном коде нет.
- `impeller_enable_lazy_shader_mode` в этой версии подключён в Android,
  а не в macOS Metal-backend.

Нового подтверждённого снижения RAM без изменения изображения и частоты
кадров не найдено. Это не доказательство невозможности исправления в
драйвере или движке: конкретное внутреннее выделение всё ещё не установлено.
Код приложения, Flutter SDK и установленная версия не изменялись;
пересборка и Flutter-тесты в этой проверке не требовались.

Расширенный воспроизводимый пример: `tool/metal_memory_probe.swift`.
Сборка: `xcrun swiftc tool/metal_memory_probe.swift -o /tmp/walone-metal-probe`.
Запуск через общую очередь: `/tmp/walone-metal-probe 1 <режим>`, где режим —
`baseline`, `shared`, `untracked`, `unretained` или `metal4` (macOS 26+).
При сообщении `active` снимать `footprint -p <PID> --noCategories --format bytes`;
`pixels=PASS` подтверждает проверку результата. Сырые замеры и логи:

## Instruments: блоки графической памяти — 20 октября 2026

Записаны Metal System Trace для отдельного Metal-примера и для копии
Walone с управляемым сценарием `music-active`. Для нативного примера также
записан Allocations; временная отладочная подпись применялась только к
диагностическому executable. Подпись и entitlements приложения не менялись.

В `native-metal.trace` при первом GPU-кадре, на 4,727554–4,737577 секунде,
видны **28 событий `Wire 4.00 MiB System Memory (Success)`**, суммарно
112 МиБ. Это операции закрепления страниц драйвером, а не 28 доказанных
новых MTLBuffer: экспорт не содержит пригодных идентификаторов ресурсов
(везде `0xffffffffffffffff`) или стеков этих операций. Таблица kernel resource
allocations пуста. Поэтому связь с ранее измеренным приростом RAM на 112 МиБ
сильна, но однозначного соответствия каждому физическому выделению нет.

В таблице публичных Metal resources отдельно видны две BGRA8-текстуры по
11,91 МиБ. Стек их создания проходит через `AGXTexture` и
`IOGPUMetalTexture initWithDevice:descriptor:...` к `main` примера. Большой
112-МиБ ресурс в этой таблице отсутствует; `currentAllocatedSize` остаётся
25 919 488 байт. После простоя readback вновь вызывает 24 операции по 4 МиБ:
суммировать все Wire-события за запись как одновременно занятую RAM нельзя.

В управляемой трассе Walone также встречаются блоки по 4 МиБ: первая серия
48 операций на 6,893–6,897 секунде и три последующие серии по 20. Здесь тоже
нет адресов/стеков, позволяющих сопоставить блок конкретному объекту Impeller.
`vmmap` показывает dirty `owned unmapped (graphics)` 9,7 МиБ до музыки,
204,2 МиБ при музыке и 12,2 МиБ после паузы. Значения сняты под Instruments,
подвержены влиянию записи и не являются новым сравнительным результатом
оптимизации. Ни 108 событий за запись, ни их сумма не означают утечку.

Отдельно исключён ложный кандидат **VM: Dispatch Continuations 112 МиБ**.
Allocations показывает стек `MTLCreateSystemDefaultDevice` → IOSurface →
CFPreferences → libdispatch → `_dispatch_alloc_try_create_heap` → `mach_vm_map`.
Но это резерв виртуальных адресов: в нативном `vmmap` dirty всего 160 КиБ,
в Walone при музыке 528 КиБ. Убирать этот резерв ради 112 МиБ RAM бессмысленно.
VM Tracker в записанном Allocations-сеансе не дал снимков; физические размеры
проверены отдельными `vmmap` и `footprint`, а не взяты из колонки Allocations.

Трассы и экспорты: `build/instruments-memory/native-metal.trace`,
`native-alloc-signed.trace`, `walone-controlled.trace`,
`metal-resource-allocations.xml`, `metal-driver-event-intervals.xml`,
`walone-driver-events.xml`, `*-4mib-bursts.json`, `walone-controlled/result.json`.
В `tool/metal_memory_probe.swift` добавлен стартовый барьер
`WALONE_METAL_PROBE_START_FILE`: Instruments можно подключить до создания
Metal device и ресурсов, затем создать файл барьера для начала сценария.

Дополнительно проверен `allowGPUOptimizedContents=false` на shared-текстурах
(режим `unoptimized` примера). В одном парном запуске активная RAM составила
149,99 МиБ с оптимизацией и 148,58 МиБ без неё; p95 отправки и ожидания GPU —
1,27 и 1,65 мс соответственно. В обоих вариантах выполнены 200 кадров и
проверены пиксели (`pixels=PASS`). Разница 1,41 МиБ не убирает большой расход,
а один парный запуск не доказывает устойчивый выигрыш; вариант не перенесён
в приложение. [Apple описывает эту настройку](https://developer.apple.com/documentation/metal/mtltexturedescriptor/allowgpuoptimizedcontents)
как компромисс между доступом CPU и производительностью GPU, а не лимит RAM.
Результаты: `build/instruments-memory/texture-options.json` и
`shared-probe.log` / `unoptimized-probe.log`.

Итог: локализованы события драйвера с подходящим размером, но внутреннее
назначение 4-МиБ блоков и стек их выделения доступные записи Instruments
не раскрыли. Подтверждённого способа убрать 112 МиБ с сохранением Impeller,
изображения и плавности пока нет. Приложение и SDK не изменены. После
диагностического target успешно собрана обычная macOS Release-сборка
с `lib/main.dart`; установленная копия не заменялась. Flutter-тесты повторно
не запускались: изменения ограничены диагностическим Swift-примером и
этим отчётом, пример скомпилирован и выполнен.

## Flutter Engine: время жизни Metal-очереди — 20 октября 2026

Проверены дополнительные точки воздействия в исходниках Flutter 3.47.4:

- `FlutterRenderer.mm:68` создаёт очередь и передаёт её как
  `present_command_queue`; `EmbedderSurfaceMetalImpeller` передаёт именно эту
  очередь в `ContextMTL::Create`. Предположение о второй независимой очереди
  Impeller в этом macOS-пути не подтвердилось.
- `render_pass_mtl.mm`, `ToMTLRenderPassDescriptor`: размеры тайлов не заданы;
  Metal выбирает их автоматически. Проверены явные 16×16 и 32×32.
  [Описание tileWidth](https://developer.apple.com/documentation/metal/mtlrenderpassdescriptor/tilewidth).
- `command_buffer_mtl.mm`, `CreateCommandBuffer`: расширенный
  `EncoderExecutionStatus` исключён в Release через `#ifndef FLUTTER_RELEASE`.
  Его отключение не объяснит расход Release-сборки.

Нативный пример расширен режимами `tile16`, `tile32`, `transient-queue`.
Последний создаёт очередь заново для каждого кадра и освобождает её после
завершения GPU-команды внутри autoreleasepool. Все варианты используют те же
две текстуры 1840×1640 BGRA8 и выполняют 200 кадров с проверкой пикселей.

| Вариант, исходный тест с паузой 50 мс после кадра | RAM, МиБ | p95 работы кадра, мс |
|---|---:|---:|
| Постоянная очередь, автоматические тайлы | 149,92 | 1,37 |
| Тайлы 16×16 | 155,14 | 1,29 |
| Тайлы 32×32 | 149,81 | 1,25 |
| Новая очередь на каждый кадр | 35,58 | 14,90 |

Это первый большой эффект: освобождение очереди снимает удержание примерно
114 МиБ между кадрами. Однако оно не предотвращает выделения на следующем
кадре. Три замера footprint — не непрерывное среднее RAM; при кратковременных
пиках они могут попадать в промежутки между работой GPU.

Повторная проверка выполнена с фиксированным бюджетом кадра (третий аргумент
примера, 20 или 60), чтобы затраты на создание очереди не скрывались за
добавочной паузой после кадра. Частота обновления музыкальной визуализации
в `music_cubit.dart` — 20 Гц, но остальные анимации интерфейса этим не ограничены.

| Частота / очередь | RAM, медиана 3 отсчётов, МиБ | p99 работы кадра, мс | Превышения бюджета / 200 |
|---|---:|---:|---:|
| 20 Гц / постоянная | 149,95 | 1,75 | 0 |
| 20 Гц / новая каждый кадр | 35,64 | 16,64 | 0 |
| 60 Гц / постоянная | 149,99 | 1,67 | 0 |
| 60 Гц / новая каждый кадр | 35,69 | 19,33 | 5 |

Пиковый footprint до окончания кадров в transient-queue — 147,38 МиБ
при 20 Гц и 184,34 МиБ при 60 Гц. Пик не устранён; на 60 Гц стал выше
обычных ~150 МиБ. Это четыре отдельных процесса, а не статистика множества
повторов или проверка плавности полного Walone. Везде `pixels=PASS`.

На уровне Engine замена одного локального указателя недостаточна: очередь
удерживают `FlutterRenderer`, `FlutterDarwinContextMetalSkia`,
`FlutterSurfaceManager` и `ContextMTL`. Кроме того, `presentSurfaces` посылает
пустой command buffer в общую очередь и ждёт `waitUntilScheduled`, сохраняя
порядок показа после ранее отправленной работы. Раздельная замена очередей
без межочередной синхронизации нарушила бы эту гарантию. В существующем
`MTLCommandQueueDescriptor` есть ограничение числа незавершённых command
buffers, но нет лимита байтов внутреннего пула; вариант с лимитом 1 уже
использован в приведённых измерениях.

Следовательно, время жизни очереди действительно влияет на удержание этих
затрат драйвером, но проверенное пересоздание на каждом кадре не является
готовой оптимизацией с сохранением плавности. Патч Engine и изменения
приложения не применены; собственный Engine не собирался. Нужна отдельная
проверка схемы асинхронного завершения/освобождения очередей на полном
рендеринге, прежде чем считать этот путь пригодным. Текущие данные не
доказывают, что такая схема будет безопасной или выгодной.

Артефакты: `build/engine-memory/results.json`, `paced-results.json`,
`*-probe.log`, `*-vmmap.txt`. Воспроизведение после сборки Swift-примера:
`probe 1 transient-queue 20` через общую resource queue. Исходный вариант:
`probe 1 baseline 20`. Swift-пример скомпилирован и выполнен; Flutter-тесты
и сборка приложения не повторялись, поскольку production-код не менялся.

Контрольная Instruments-запись `transient-paced.trace` подтверждает механизм:
для PID 38348 первый кадр содержит 28 событий Wire по 4 МиБ, следующие
199 кадров — по 26; после шестисекундной паузы readback добавляет ещё 24.
Итого 5226 событий в 201 серии (разделение серий по промежутку >25 мс).
Это повторное закрепление страниц, не 5226 одновременно живых выделений.
В исходной постоянной очереди перед readback была только начальная серия
из 28. Следовательно, освобождение очереди заменяет длительное удержание
памяти многократной работой драйвера на каждом кадре. Файл с точными временами:
`build/engine-memory/transient-wire-bursts.json`; исходные события:
`transient-driver-events.xml`. Под Instruments выполнены все 200 кадров,
проверка пикселей прошла. Отладочные процессы завершены.
