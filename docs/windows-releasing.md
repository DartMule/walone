# Выпуск Walone для Windows

Windows x64 распространяется установщиком Inno Setup 6. Установка выполняется
для текущего пользователя в `%LOCALAPPDATA%\Programs\Walone`, без UAC.
Создаются ярлык в меню «Пуск» и запись удаления в настройках Windows.
Приложение, аудиоресурсы, SQLite и Visual C++ Runtime DLL поставляются вместе.
Для входа VK дополнительно нужен WebView2 Runtime.

## Проверки и QA-сборка

В GitHub Actions задача `windows` выполняет проверку ресурсов, анализ,
Flutter-тесты, Release-сборку и упаковку неподписанного QA-установщика.
Установщик и SHA-256 сохраняются как артефакт `walone-windows-x64-qa`.
CI не публикует релиз и не получает ключи подписи.

На Windows нужны Flutter из `.fvmrc`, Visual Studio с C++/Windows SDK,
Python 3 и Inno Setup 6. Создание ссылок плагинов Flutter требует режима
разработчика Windows либо запуска Flutter из терминала с правами администратора.
Сами приложение и установщик работают с обычными правами пользователя.
Из корня репозитория:

```powershell
fvm flutter pub get --enforce-lockfile
fvm flutter analyze --no-pub
fvm flutter test --no-pub --concurrency=1
fvm flutter build windows --release --no-pub
./tool/windows_release.ps1 -SkipBuild -Unsigned
```

Результат: `dist/windows/walone-<version>+<build>-windows-x64-setup.exe`
и соответствующий `.sha256`. Неподписанный установщик предназначен для QA;
автообновления такой копии отключены. Перед ручной установкой завершите Walone
через меню приложения. Установщик не принудительно завершает процессы.

Скрипт работает и без FVM: параметр `-Flutter` задаёт путь к `flutter.bat`.
`-CrtDirectory` позволяет явно указать каталог `Microsoft.VC143.CRT` из
установленной Visual Studio. По умолчанию он находится через `vswhere`.
Сборочный каталог не изменяется: упаковка и подпись используют отдельную копию.

## Подписанный выпуск

Нужен действующий Authenticode Code Signing сертификат в хранилище
текущего пользователя Windows и `signtool.exe` из Windows SDK в `PATH`
(или параметр `-SignTool`). Закрытый ключ остаётся в хранилище Windows или
у провайдера сертификата; скрипт получает только SHA-1 thumbprint сертификата.

```powershell
$env:WALONE_WINDOWS_CERTIFICATE = '<40 hex characters>'
./tool/windows_release.ps1 -SkipBuild
```

Скрипт подписывает `walone.exe`, установщик и деинсталлятор с SHA-256 и RFC3161
timestamp; проверяет доверие и совпадение сертификата для EXE и установщика.
Затем создаёт файл SHA-256. Неподписанный выпуск требует явного `-Unsigned`.
Windows-сертификат не заменяется сертификатом Apple Developer ID.

Номер версии берётся из `pubspec.yaml`; скрипт отклоняет старую сборку с другим
номером. Для публикации увеличивайте номер версии/сборки, проверяйте установку,
повторную установку и удаление в тестовом профиле. Отдельно проверьте компьютер
без Visual Studio/VC Runtime и WebView2, а также реальный ПК Intel/AMD.

Готовый подписанный установщик и `.sha256` загрузите в GitHub Release
репозитория `DartMule/walone`. Тег должен иметь вид `v<major>.<minor>.<patch>`;
имя установщика сохраняйте точно в формате, созданном скриптом. Сначала
подготовьте draft и проверьте вложения. Обновления видят только опубликованный
стабильный релиз, не draft/prerelease. Коммиты, теги и публикация не выполняются
сборочным скриптом.

## Обновления приложения

При запуске Windows-приложение проверяет собственную Authenticode-подпись,
затем последний стабильный GitHub Release. Новый Windows-установщик загружается
в фоне в папку `Updates` рядом с данными Walone. Проверяются:

- Числовой номер версии и сборки, отсутствие отката, совпадение с тегом.
- Имя файла, адрес нашего репозитория, размер (до 256 МиБ).
- SHA-256 из `digest` GitHub Release Asset API.
- Доверенная Authenticode-подпись тем же сертификатом, что у работающей Walone.

Готовая версия отображается в настройках и кнопкой рядом с ними в боковой панели. Кнопка «Обновить и перезапустить»
сохраняет данные и завершает приложение; отдельный процесс ждёт завершения,
повторно проверяет хеш/подпись, запускает установщик и возвращает Walone.
При обычном штатном выходе подготовленное обновление устанавливается без
повторного запуска. Закрытие окна в трей не является выходом. Если процесс не
завершился за 30 секунд, установщик не запускается. Системный сон, убийство
процесса и завершение Windows не гарантируют выполнение штатного выхода.

Неполная загрузка или ошибка проверки не изменяет установленную программу.
Без сети, при отсутствии Windows-вложения или ошибке GitHub приложение
продолжает работать; повторная проверка доступна в настройках.
При смене сертификата требуется ручная установка нового подписанного выпуска.
Первый подписанный Windows-релиз также устанавливается вручную поверх QA-копии.

- Windows x64 Release и упаковка Inno Setup — passed.
- Нативный Windows-тест полей прозрачности/контраста и соответствия настройки
  прозрачности реестру — 1 passed.
- Установка, повторная установка, проверка CRT DLL/регистрации и удаление

  хеша, размера, подписи и версии покрыты целевыми тестами.

`.local/windows-parity/`; установщик — в `dist/windows/`. Проверки выполнялись
в Windows 11 ARM с x64-приложением; физический ПК Intel/AMD отдельно не проверялся.
