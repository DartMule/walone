# Датчик вибрации и граница привилегий

Эксперимент работает с акселерометром корпуса совместимого Mac через SPU HID.
Это измерение вибрации в g, а не силы отдельной клавиши. Обычное озвучивание
не требует датчика и остаётся доступным без его потока.

## Запуск

Сначала соберите Walone.app и завершите остальные копии приложения.
Из корня Flutter-проекта после осознанного разрешения аппаратной сессии:

```sh
bash tool/sensor_experiment.sh --approved-root-read "$PWD/build/macos/Build/Products/Release/Walone.app"
```

Флаг `--approved-root-read` разрешает только открытие датчика и чтение.
Если пассивный датчик не выдаёт отсчёты, отдельный режим активации:

```sh
bash tool/sensor_experiment.sh --approved-root-activation "$PWD/build/macos/Build/Products/Release/Walone.app"
```

На рабочем Mac запускайте сессию через общую resource_queue. Скрипт собирает
`tool/sensor-probe.c` в `build/sensor/sensor-probe`, запрашивает sudo в терминале
только для probe и передаёт поток обычному GUI через stdin. Пароль не передаётся
приложению. Сессия ограничена 120 секундами; служба не устанавливается.

## Что меняет активация

Probe открывает SPU HID акселерометр usage page 0xFF00, usage 3. Он не читает
символы клавиатуры, не использует сеть и не запускает сторонний код.
Режим `--activate` поэтапно запрашивает reporting, power и ReportInterval=1000
у драйвера акселерометра. Это изменение свойств живого драйвера IOKit.

При штатном выходе, SIGINT и SIGTERM probe пытается вернуть исходные свойства.
Для отсутствовавших reporting/power используется 0; точное внутреннее состояние
недокументированного драйвера этим не гарантируется. SIGKILL и авария не позволяют
выполнить очистку. При ошибке восстановления может потребоваться перезагрузка.
Глобальный доступ к клавиатуре предоставляется только обычной Walone через
«Мониторинг ввода», а не root-процессу и не Terminal.

## Измерения

В настройках откройте «Эксперимент с вибрацией». Для калибровки выключите звук,
соберите по 20–30 отдельных нажатий одной клавиши и пальца в трёх режимах,
затем сохраните сводку. Импорт калибровки принимает schema 5 с включённым
датчиком, выключенным звуком, без пропусков и с разделёнными центральными
диапазонами. Непригодная сводка не заменяет действующую калибровку.

Swift обрабатывает поток и сопоставляет отсчёты с событиями клавиатуры;
Flutter получает только состояние для интерфейса. Экспорт сохраняет амплитуды,
причины пропусков и диагностику задержек в прежнем формате schema 5.
`tool/sensor_check.swift` проверяет эту цепочку искусственным сигналом без sudo
и без обращения к аппаратуре. Команда приведена в README проекта.
