## Подготовка гостевой ОС

1. Создать Windows ARM64 ВМ на QEMU backend с аппаратной виртуализацией CPU
   (не эмуляцией x64). Установить Windows и UTM Windows Guest Tools с аудио.
   В UTM 5.0.8 ускорение DirectX экспериментальное: использовать GPU-дисплей
   `-gl` и Renderer Backend Default/ANGLE (Metal), затем проверить драйвер
   и реальный рендеринг Walone. При сбоях сохранять логи и сравнивать
   с обычным дисплеем; производительность без ускорения не считать эталонной.
2. Установить Git, Python, FVM, Visual Studio с Desktop development with C++,
   Windows SDK и WebView2 Runtime. Проверить компоненты сборки нужной архитектуры.
3. Получить отдельную копию проекта. Выполнить `fvm install`, затем команды ниже.
4. Убедиться, что `flutter doctor -v` подтверждает Windows toolchain.
5. Зафиксировать архитектуру полученного EXE: проверка ARM64 и запуск x64
   через эмуляцию Windows дают разные свидетельства совместимости.
6. После подготовки сохранить один чистый снимок ВМ. Тестовые медиатека,
   профиль WebView и автозапуск должны принадлежать только гостевой ОС.

В PowerShell из корня проекта, последовательно:

```powershell
fvm flutter doctor -v
fvm flutter pub get --enforce-lockfile
python tool/check_migration.py
fvm flutter analyze --no-pub
fvm flutter test --no-pub --concurrency=1
fvm flutter build windows --release --no-pub
fvm flutter test integration_test/desktop_native_test.dart -d windows --no-pub --concurrency=1
fvm flutter test integration_test/statistics_native_test.dart -d windows --no-pub --concurrency=1
fvm flutter test integration_test/media_native_test.dart -d windows --no-pub --concurrency=1
fvm flutter test integration_test/audio_frame_test.dart -d windows --no-pub --concurrency=1
```

Затем проверить keyboard_native_test, text_editing_native_test и
renderer_performance_test с учётом контрактов платформ. Для проверки доступности:

```powershell
fvm flutter drive --driver=test_driver/integration_test.dart --target=integration_test/accessibility_native_test.dart -d windows --no-pub
```

`keyboard_permission_native_test` проверяет отказ TCC в macOS и не заменяет
Windows-проверки Raw Input. В `keyboard_native_test` проверки `sensorStatus` и `sensorConfigure`,
отсутствующие в Windows-мосте, ограничены macOS. Пропуск всего
теста клавиатуры не считается проверкой Windows.
Автотесты могут менять данные приложения: использовать только тестовый профиль.

переход из меню в «Мою музыку». Отдельно наблюдалась штатная остановка
по команде «Следующий» в конце списка. Непрерывная чёрная анимация
при воспроизведении и статичный знак на паузе видны на снимках.
Тёмная тема, высокая контрастность и DPI после этой правки отдельно вручную
не переключались. Параллельные изменения других функций не относятся к
этой проверке; архив содержит проверенную гостевую копию проекта.

## Границы результата

- Реальный импорт YouTube (`DTi8wZ1a1TA`, тестовый ролик yt-dlp) и SoundCloud
  (`ethmusic/lostin-powers-she-so-heavy`, fixture из upstream) прошёл:
  загрузка, обработка FFmpeg, сохранение и нативное воспроизведение,
  2 теста без ошибок. Это публичные тестовые записи, без входа в аккаунты.
- WebView2, вход VK пользователем, повторное использование сохранённой сессии
  и импорт одного трека по предоставленной ссылке проверены. Массовый импорт
  плейлистов и закрытая медиатека отдельно не проверялись.
- В проверенной сборке r4 автообновление доступно только на macOS,
  как и нативные ползунки громкости в системном меню. В Windows есть
  управление громкостью через подменю и плеер в трее, основной
  плеер/ползунки в окне, визуализация, общая пауза, атмосфера и таймеры.
  Более поздние установщик и механизм подписанных Windows-обновлений
  описаны в [инструкции выпуска](windows-releasing.md).
- Mac разблокирован пользователем, ручная проверка продолжена с обычным
  токеном Windows. Пользователь подтвердил работу своей мыши внутри ВМ;
  ограничение касается автоматической передачи щелчков CUA. Проверка
  Explorer → Walone выполнена пользователем и подтверждена по UI и SQLite;
  полный функциональный паритет пока не подтверждён.
- Пакет r4 является полной папкой Release, не установщиком. Запуск на чистой
  Windows без Visual C++ Runtime отдельно не проверялся.

- Датчик вибрации Apple SPU в Windows не предоставляется. Проверить обычное
  озвучивание без датчика и корректное отсутствие недоступных настроек.
- Разрешения macOS, Keychain, SMAppService и AXTree проверяются на Mac;
  на Windows проверяются соответствующие сценарии Raw Input, автозапуска,
  WebView и доступности Windows.
- Аудиоустройство гостя виртуальное. Физическое отключение Bluetooth/USB,
  реальные задержки и сон физического ПК требуют отдельной Windows-машины.
- Запуск x64 EXE в Windows ARM не заменяет проверку на Intel/AMD Windows.
- Снимок с открытой авторизованной сессией содержит её данные; чистый снимок
  сохранять до входа в сервисы. Не переносить профиль VK с Mac.

Приёмка завершена только после заполнения результатов матрицы; успешные
unit-тесты или сборка сами по себе не подтверждают полную совместимость.
